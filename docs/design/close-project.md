# プロジェクトを閉じる機能の設計

開いている `.lbproj` または `.sqlite` を閉じ、同じウィンドウで起動時の「プロジェクト未選択」画面に戻ります。利用者はアプリを起動し直さずに、別のプロジェクトを開いたり、新規作成したりできます。

## 1. 操作と画面

「ファイル」メニューの「ウィンドウを閉じる」の直前に「プロジェクトを閉じる」を追加します。プロジェクトを開いていて、保存や確認ダイアログなどの処理を実行していないときに選択できます。

専用のキーボードショートカットは初版では割り当てません。`⌘W` とタイトルバーの閉じるボタンはウィンドウを閉じ、`⌘Q` はアプリを終了します。いずれも現在の未保存確認を経由します。最後のウィンドウを閉じるとアプリが終了します。

プロジェクトを閉じた後は、タイトルを「Light Bringer」に戻し、プロジェクト名、グラフ、一覧、詳細フォームを画面から取り除きます。「新規」「開く」「JSON 取込」を選択できます。保存、別名保存、JSON 書出には開いているプロジェクトが必要です。

## 2. 未保存の変更

既存の `Editor::has_changes` で判定します。グラフ、モード、確定済みのノード配置の変更に加え、詳細フォームの反映前の入力や新規ノード・関係の編集中のフォームも含みます。表示上のパンやズーム、保存形式の更新が可能であることだけでは、未保存の変更に該当しません。

未保存の変更がある場合は「未保存の変更があります」と表示し、「保存」「破棄」「キャンセル」を提示します。既定は「保存」です。Esc キーやダイアログを中断した場合は「キャンセル」と同じ結果にします。

| 条件または選択 | 結果 |
| --- | --- |
| 未保存の変更なし | 確認や書き込みを行わずに閉じる |
| 保存 | 通常の保存処理でフォームを検証・反映し、現在のファイルに保存する。保存が成功した時点で閉じる |
| 破棄 | 編集中のグラフとフォームを破棄して閉じる。プロジェクトファイルへの書き込みは発生しない |
| キャンセル | 開いていたプロジェクトに戻る。編集中のグラフ、フォーム、選択、編集ロックを保持する |
| フォームの検証失敗 | エラーを表示し、入力と編集ロックを保持する。フォームの修正後に再試行できる |
| ファイル保存の失敗 | エラーを表示し、編集中の内容と編集ロックを保持する。成功したフォーム反映は編集中のグラフに残る。保存の再試行や、別名保存での退避ができる |

保存時の外部変更検出と同期エラーの扱いは、既存の保存契約に従います。`.lbproj` の置換後に同期が失敗した場合も、エラーを表示して編集画面に戻ります。 [保存と同時編集](project-file.md#4-保存と同時編集)

## 3. 状態の初期化とロック解放

確認不要、「破棄」選択、保存成功のいずれかで、閉じる処理を確定します。確定時に編集中のグラフ、フォームと選択、キャンバスの表示位置・倍率とドラッグ状態、保存状態、ステータスとエラー表示を初期化します。フォーカスをウィンドウのルートに戻して再描画します。

確認中と保存中は `Editor` がプロジェクトを保持します。確定時に `Editor` と完了した処理が参照する `Arc<ProjectFile>` を破棄します。最後の参照とともに編集ロックのファイルハンドルを閉じます。後続のセッションが同じロックを使えるよう、ロックファイル自体は残します。

ロックの解放と画面の更新は、次のファイル操作を受け付ける前に完了させます。閉じた直後に同じファイルを開けば、ディスクに保存された内容から編集を始められます。

## 4. 実装方針

現在の `Command::Close` はウィンドウを取り除きます。プロジェクトを閉じるアクションを別に設け、既存の未保存確認と `save` を共用します。完了時だけ処理を分岐させることで、閉じる経路ごとの保存結果の判定をそろえます。 [ファイル操作の実装](../../apps/desktop/src/ui/files.rs)

| 実装箇所 | 変更内容 |
| --- | --- |
| `ui/mod.rs` | `CloseProject` アクションとメニュー項目を追加する。プロジェクトがあり、処理中でないときにアクションを登録する |
| `ui/files.rs` | `Command::CloseProject` と `Outcome::ProjectClosed` を追加する。確認と保存を共用し、結果に応じて既存の未選択画面へ遷移する |

実行時にも `Editor::command` でプロジェクトの有無と `busy` を確認します。操作を受け付けた時点から結果を反映するまで `busy` を保持し、確認中や保存中の再実行を防ぎます。未選択時や処理中にアクションが届いても、その場で処理を打ち切ります。保存の失敗やキャンセル時は `busy` を解除し、同じプロジェクトの編集に戻ります。

## 5. 検証項目

ファイル操作の既存の GPUI テストと同じ方法で、操作後の編集状態とディスク上の内容を確認します。メニューの選択可否とウィンドウ操作は macOS でも確認します。

| 確認する場面 | 期待する結果 |
| --- | --- |
| 保存済みの `.lbproj` と `.sqlite` を閉じる | 確認なしで未選択画面に戻る。ファイルは更新されない。形式更新が可能なだけの旧形式も同様に扱う |
| フォームに反映前の入力がある状態で「保存」 | 入力とグラフの変更が再オープン後に読み込める。閉じる途中の保存中はロックを保持する |
| 未保存の変更がある状態で「破棄」 | 再オープンで最後に保存した内容が表示される。別セッションでも開ける |
| 未保存の変更がある状態で「キャンセル」 | 入力と選択が残り、別セッションからの編集は引き続き拒否される |
| 無効なフォーム入力、外部変更、または同期失敗で保存できない | エラーが表示され、編集中の内容とロックを保持する。エラーに応じて修正や再保存を続けられる |
| 未選択時、または確認中と保存中に再実行する | 確認や保存の処理が追加で開始されない |
| 閉じた後に「開く」「新規」「JSON 取込」を選ぶ | 同じウィンドウで操作できる。前のプロジェクトのフォーム、表示位置、エラーが新しいプロジェクトに引き継がれない |
| `⌘W`、タイトルバーの閉じるボタン、`⌘Q` を使う | 未保存確認が働き、操作成立後は従来どおり最後のウィンドウとともに終了する |
